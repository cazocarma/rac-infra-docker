## Pruebas nuevas exigidas

`TestPhotoQueuePostgres` usa un LOGIN real sin acceso directo a tablas. Comprueba
ocho claims simultáneos sobre un job, release distinto, recibo inválido,
rollback por fallo de trigger, replay exacto/conflictivo, intento vencido y
obsoleto, máximo de intentos, vencimiento al COMMIT y replay de un resultado ya
confirmado después del vencimiento. También rechaza superusuario y drift de
grants. El resultado es técnico: nunca aprueba/publica una foto.

El ensayo conjunto con RustFS usa ingesta Get/Put raw, lector Get raw y staging
Get/Put JPEG, en buckets distintos. Deniega accesos cruzados, escritura del
lector, borrado, listado, cambios de ACL/policy y lectura anónima. El worker lee
bytes reales, ejecuta Tesseract nativo, verifica el JPEG escrito y confirma un
resultado `contact_correction_required` con el usuario SQL restringido.

El laboratorio de procesamiento conservó el corpus sintético de similitud:
144/144 variantes detectadas y 0 matches entre 276 pares no relacionados, con
umbral 8 **solo del fixture**. No se configura ese umbral en el runtime ni se
interpreta como rendimiento de producción o curación D13.
